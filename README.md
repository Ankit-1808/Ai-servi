# NICE Queue Monitor — OCR Debug Prototype

This is the Phase 1–3 deliverable from the implementation prompt. It captures a selected NICE CXone dashboard window, displays the live preview, runs one OCR pass using a locally hosted Tesseract.js distribution, and shows each recognized word with confidence and bounding-box coordinates.

## Structure

```text
index.html
styles.css
README.md
js/
  app.js
  capture.js
  config.js
  ocr-engine.js
  preprocessing.js
  ui.js
vendor/
  tesseract/
    tesseract.min.js
    worker.min.js
    tesseract-core.wasm.js
    eng.traineddata
```

The `vendor/tesseract/` files are intentionally not downloaded or generated by this project. Copy the organization-approved Tesseract.js distribution there, then update `js/config.js` if its filenames differ. Runtime dependencies are local only.

## Run

Serve this folder through an approved local HTTP server. For example, use the organization-approved static-file server and open its `http://localhost:<port>/index.html` URL in Edge. `file://` is not recommended because module loading and display capture require a secure/allowed context.

1. Click **Start Capture**.
2. Choose the NICE CXone dashboard window in Edge’s sharing dialog.
3. Confirm the live preview is visible.
4. Click **Capture Frame & Run OCR**.
5. Inspect the OCR debug table and browser console (`console.table` contains the same word records).

## Configuration

`js/config.js` contains:

- `workerPath`, `corePath`, `langPath`: local Tesseract worker, WASM/core, and language-data locations.
- `language`: currently `eng`.
- `capture`: native display-capture constraints; audio is disabled and capture is limited to a low frame rate.
- `preprocessing`: default mode (`none`); the UI also exposes grayscale, high-contrast, and binary threshold modes.
- `minimumOcrConfidence`: reserved for the next phase; this prototype displays all returned words for debugging.

## Expected result

The table reports `Text`, `Confidence`, `X`, `Y`, `Width`, and `Height`. Coordinates are the OCR bounding-box coordinates in the captured frame. The app also logs the normalized records in the console.

## Common failures

- **Local OCR library could not load:** verify `vendor/tesseract/tesseract.min.js` exists and is reachable from the page.
- **Worker/core/language errors:** verify the three configured paths and that `eng.traineddata` is present where `langPath` points.
- **Capture denied:** allow screen sharing and select the NICE window.
- **Preview freezes or says capture stopped:** the shared window/track ended; click Start Capture again.
- **Few or no words:** ensure the dashboard is visible and readable, then compare preprocessing modes. The app does not convert failed OCR into fake timer values.

If a real-dashboard test fails, provide the sanitized OCR table/console output, the browser console error, selected preprocessing mode, and the Tesseract distribution/version. Do not provide screenshots containing customer or employee information.

## Python + Playwright monitor

The alternative implementation is `nice_queue_monitor.py`. It uses Playwright with installed Microsoft Edge and reads visible DOM text, so it does not need Tesseract or the local web UI.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python nice_queue_monitor.py "https://<your-nice-dashboard-url>"
```

The first run opens a dedicated `.playwright-profile` directory. Complete NICE login manually if prompted. The monitor then prints each configured queue, timer, association confidence, and console alerts. Stop with `Ctrl+C`.

Playwright can inspect HTML text, not pixels. If the NICE dashboard renders its queue data only inside a canvas/image, this alternative cannot detect it; the browser DOM must expose the queue names and timers.

## Python + OCR monitor

Use `nice_queue_monitor_ocr.py` when the dashboard is visual/canvas-based:

```powershell
python -m pip install -r requirements.txt
python nice_queue_monitor_ocr.py "https://actual-nice-dashboard-url"
```

This captures the visible Edge page with Playwright and runs Tesseract OCR over each screenshot. Install the native Tesseract engine separately through your approved company software channel. If `tesseract.exe` is not on `PATH`, provide it explicitly:

```powershell
python nice_queue_monitor_ocr.py "https://actual-nice-dashboard-url" --tesseract-cmd "C:\Program Files\Tesseract-OCR\tesseract.exe"
```

## Recommended exact-reading monitor

If the NICE tiles expose their text as HTML, use `nice_queue_monitor_dom.py` instead of OCR. It reads each tile through the browser DOM and selects the timer immediately before that tile's `Longest waiting time` label, preventing header timestamps from being mistaken for wait values:

```powershell
python nice_queue_monitor_dom.py "https://na1.nice-incontact.com/apps/#/dashboard/wrapper/supervisor-dashboards"
```

This is more reliable than any screenshot OCR for this dashboard. If the DOM does not expose the tile text, use the OCR monitor as a fallback.

## Notifications

Notifications are disabled by default. Enable them explicitly with `--notifications teams`, `--notifications outlook`, or `--notifications both`. The monitor sends only on a new confirmed alert and on recovery; it does not repeat notifications every poll.

Teams uses separate approved incoming webhook URLs by destination:

```powershell
$env:NICE_TEAMS_MANAGED_SERVICES_WEBHOOK_URL = "<managed-services-webhook-url>"
$env:NICE_TEAMS_SUPPORT_SERVICES_WEBHOOK_URL = "<support-services-webhook-url>"
# Required for a real Teams mention of the Service Coordinator identity/tag:
$env:NICE_SERVICE_COORDINATOR_MENTION_ID = "<approved-teams-mention-id>"
$env:NICE_SERVICE_COORDINATOR_MENTION_NAME = "Service Coordinator"
python nice_queue_monitor_ocr.py "<nice-url>" --notifications teams --tesseract-cmd "C:\Program Files\Tesseract-OCR\tesseract.exe"
```

Routing is fixed as follows: `EEC Calls` and `EEC Chats` go to Managed Services; all other queues go to Support Services. `Service Coordinators Calls` includes the configured Service Coordinator mention in Support Services. Without the mention ID, the message contains the visible text `@Service Coordinator` but will not create a real Teams mention.

Outlook requires approved SMTP settings in the current PowerShell session:

```powershell
$env:NICE_OUTLOOK_SMTP_HOST = "<approved-smtp-host>"
$env:NICE_OUTLOOK_SMTP_PORT = "587"
$env:NICE_OUTLOOK_SMTP_USERNAME = "<approved-sender-account>"
$env:NICE_OUTLOOK_SMTP_PASSWORD = "<approved-password-or-app-password>"
$env:NICE_OUTLOOK_FROM = "<sender-address>"
$env:NICE_OUTLOOK_TO = "<recipient-address>"
python nice_queue_monitor_ocr.py "<nice-url>" --notifications outlook --tesseract-cmd "C:\Program Files\Tesseract-OCR\tesseract.exe"
```

Use `--notifications disabled` to turn delivery off. Do not commit webhook URLs or passwords. Confirm the Teams webhook and SMTP route with your company security/messaging administrators before enabling delivery.

## Deliberate scope boundary

Queue matching, dynamic timer association, threshold rules, alerting, localStorage, Teams, email, and monitoring loops are not included yet. They should be added only after this OCR output is validated against the real NICE dashboard.
